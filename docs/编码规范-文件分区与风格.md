## 1. 范围

### 1.1 适用范围

本规范适用于下列代码：

1. **`User/` 目录**下手写模块：Bsp、Common、Service、App、Config；
2. **`Core/Src`、`Core/Inc`** 中位于 `USER CODE` 区域内的用户驱动代码（`Drv_*` 等）；
3. 上述模块对应的头文件与源文件。

### 1.2 不适用范围

下列代码**不强制**套用本规范的分区编号，但位于 `USER CODE` 内的用户新增符号仍须遵循命名与注释要求：

- CubeMX 生成的 `MX_*`、`HAL_*` 框架代码及其 `HAL_*_MspInit` 等；
- `Drivers/` 下 STM32 HAL、CMSIS 等第三方库。

### 1.3 规范用语

本文采用下列用语表示约束强度：

| 用语 | 含义 |
|------|------|
| **必须** | 强制性要求，违反即视为不合规 |
| **应当** | 强烈建议，无充分理由不得偏离 |
| **可以** | 允许的可选做法 |

## 2. 术语与缩写

| 术语 | 定义 |
|------|------|
| 对外接口 | 在模块 `.h` 第 5 区声明、供其他 `.c` 文件调用的函数、宏、类型或变量 |
| 私有实现 | 仅在模块 `.c` 内可见的 `static` 函数、变量、宏及类型 |
| 分区 | 源文件/头文件中按固定编号划分的逻辑区块（见第 5 章） |
| IWYU | Include What You Use：仅包含本文件直接使用的符号之来源头文件 |
| USER 区 | CubeMX 在 `Core` 文件中预留的 `/* USER CODE BEGIN … */` 槽位 |
| 匈牙利前缀 | 以类型/作用域信息作为标识符前缀的命名方式（见第 4.5 节） |

| 缩写 | 含义 |
|------|------|
| BSP | Board Support Package，板级支持包（`User/Bsp`） |
| Drv | 用户驱动层（`Core/Src` 中 `Drv_*` 接口） |
| HAL | STM32 硬件抽象层 |

## 3. 总则

固件代码须遵循下列设计原则：

1. **接口与实现分离**  
   头文件仅声明**对外接口**（宏、类型、变量、函数原型）；私有宏、类型、变量及函数必须定义在源文件中，且以 `static` 限制链接范围（对外变量除外）。

2. **最小依赖**  
   每个 `.c` 源文件必须直接 `#include` 其所用函数、类型、宏的**定义或声明所在**的头文件，不得依赖「A 包含了 B、B 包含了 C」的传递包含来间接获得 C 中的符号。

3. **少用跨文件全局变量**  
   多个 `.c` 之间尽量不要用全局变量直接传数据；能用函数接口（读/写、初始化、一次取快照）封装的，优先封装。实在必须让别的文件直接访问的变量，命名加 `g_` 前缀，在定义它的 `.c` 第 4 区定义，并在对应 `.h` 第 4 区写 `extern` 声明。

4. **同一类问题，同一套规则**  
   凡本文档已写明的规则（命名、分区、注释、分层、返回值等），新增与修改代码时**必须**与现有模块保持一致，不得在同一工程里混用多套个人习惯。  
   「同类问题」指下表所列范畴；表中每一行只能选用**一种**工程约定：

   | 范畴 | 工程约定（示例） | 不得混用 |
   |------|------------------|----------|
   | 对外函数命名 | `Bsp_` / `Cmn_` / `Svc_` / `App_` / `Drv_` 前缀 | 同一层有的加前缀、有的不加 |
   | 函数命名模板 | `[组织段][名词语义段_…][动作段]`；组织段含 ①层级前缀 ②`Loc_` ③模块 ④子域；`static` 无 ①② | 段类/段顺序混乱或可见性标记混用 |
   | 变量命名 | 匈牙利 + `g_` / `s_` / `ls_`（见第 4.5 节） | `sum_A` 与 `fSumA` 并存 |
   | 类型命名 | 大驼峰 + `_t`（`RfqFrame_t`） | `rfq_frame_t` 与 `RfqFrame_t` 并存 |
   | 源文件/头文件分区 | 1～9 区（或 Cube USER 区映射）顺序固定 | 有的文件有第 9 区、有的省略 |
   | 空分区 | 写 `/* 无 */` | 有的空段不写、有的写说明性废话 |
   | 函数返回值 | 通用用 `Status_t`，模块错误用各自枚举 | 同一层有的返回 `int`、有的返回枚举 |
   | 调试打印 | `BSP_LOG_PRINTF` | 热路径随意裸 `printf` |
   | 层间调用 | App 只调 `Svc_*` 等（见第 9 章） | App 直接 `Drv_*` / `HAL_*` |

   若确需变更工程级约定（例如统一重命名一类符号），**须先修订本文档并在评审中说明**，再批量修改；不得在未改规范的情况下，单文件私自采用另一套写法。

5. **可文档化**  
   每个源文件、头文件及每个对外接口必须配备 Doxygen 注释（见第 7 章）。

6. **分层清晰**  
   纵向须 App → Service → Drv → HAL 单向依赖，禁止跨层与反向调用；横向模块 Common / Config / Bsp 可被各层使用，其中仅 Bsp 对下可调用 HAL，Common 不得依赖 HAL。详见第 9 章。

## 4. 命名规范

### 4.1 文件命名

| 规则 | 说明 |
|------|------|
| 模块源文件 | 小写字母 + 下划线，成对出现，如 `pendulum_service.c` / `pendulum_service.h` |
| 单头文件模块 | 允许仅含 `.h`，如 `config.h` |
| 禁止 | 模块文件名中使用空格、大驼峰（历史遗留文件应逐步迁移） |

### 4.2 头文件保护宏

| 规则 | 说明 |
|------|------|
| 格式 | `文件名大写_H`，如 `MOTOR_SERVICE_H`、`BSP_H` |
| 结尾 | `#endif /* MOTOR_SERVICE_H */` |
| 禁止 | 前导或连续下划线（`__XXX__`、`_XXX`），其为 C 标准保留标识符 |

### 4.3 函数命名

#### 4.3.1 统一模板

函数名（头文件声明的接口与 `.c` 内 `static` 私有函数**共用**同一套拼段规则）自左向右由**三类段类**顺序拼接，语义范围**从大到小**；**动作段**有且仅有一个，且**固定在最后**。

**统一模板（从左到右）：**

```text
[组织段：层级前缀_][组织段：Loc_][组织段：模块_][组织段：子域_][名词语义段_…][动作段]
```

**段类总览（按出现顺序）：**

| 顺序 | 段类 | 在模板中的位置 | 作用 |
|------|------|----------------|------|
| 1 | 组织段 | 最前，可含 1～4 个「段」 | 表归属、层内标记与模块内分组 |
| 2 | 名词语义段 | 组织段之后、动作段之前 | 表操作涉及的名词性语义（可连续多个） |
| 3 | 动作段 | **末尾** | 表动词（做什么） |

**段明细（按段类 → 段顺序；与模板从左到右一致）：**

| 顺序 | 段类 | 段 | 是否必须 | 含义 | 示例 |
|------|------|----|----------|------|------|
| ① | 组织段 | 层级前缀 | 头文件接口**必须有**；`static` 私有**不得有** | 所属层/库 | `Bsp_`、`Cmn_`、`Svc_`、`App_`、`Drv_` |
| ② | 组织段 | `Loc_` | 可选；**仅纵向层层内跨文件接口** | 层内标记，紧接层级前缀之后 | `Drv_Loc_`、`Svc_Loc_`、`App_Loc_` |
| ③ | 组织段 | 模块 | 可选 | 源文件对应的功能模块名 | `PendulumService_`、`SimulinkProtocol_` |
| ④ | 组织段 | 子域 | 可选 | 同一 `.c` 内的逻辑分组或外设子系统 | `EncoderUart_`、`ADC_`、`PWM_`、`RFQ_` |
| ⑤ | 名词语义段 | （可 0～N 个） | 可选 | 动作前的名词短语；多个时从大到小；最末段通常为最具体操作主体 | `FeedbackData_`、`HwErrorFlags_`、`AtIrqEntry_`、`Int16LE_` |
| ⑥ | 动作段 | 动作 | **必须** | 动词或动词短语，**固定在末尾** | `Get`、`Set`、`Read`、`Pack`、`Latch` |

**拼段规则：**

1. **不是每一段都必须出现**；命名时自右向左（先定动作段，再按需向左补足）按语义从大到小选取各段。  
2. **禁止**动作写在中间或开头（如 `GetFeedbackData`、`Is_Empty`）。  
3. **禁止**多个名词语义段粘连为一个单词（如 `HwErrorFlagsAtIrqEntry` → 应拆为 `HwErrorFlags_AtIrqEntry_`）。  
4. 仅含动作、无名词语义段时，可为 `层级前缀_动作` 或 `子域_动作`（如 `Bsp_Init`、`Drv_PWM_Enable`）。

**三级可见性（决定组织段 ①② 如何出现）：**

| 级别 | 组织段 ① 层级前缀 | 组织段 ② `Loc_` | 声明位置 | 典型命名 |
|------|-------------------|-----------------|----------|----------|
| 上层接口 | 必须有 | 不得有 | 纵向层 `.h` **5.1** / `.c` **7.1** | `Drv_EncoderUart_HwErrorFlags_Log` |
| 层内接口 | 必须有 | **必须有** | 纵向层 `.h` **5.2** / `.c` **7.2** | `Drv_Loc_EncoderTrigger_SendOne` |
| 文件私有 | 不得有 | 不得有 | `.c` 第 6 / 8 区，`static` | `EncoderUart_LatchIdx_Get` |

横向模块 `User/Bsp`、`User/Common` 无层内 `Loc_` 接口，不适用上表「层内接口」行；其头文件第 5 区、源文件第 7 区保持单区，按功能分子节即可。

#### 4.3.2 头文件接口与文件私有的差别

下表按**段类 → 段**顺序，对照三类可见性下各段是否出现：

| 段类 | 段 | 上层接口（5.1） | 层内接口（5.2） | 文件私有（`static`） |
|------|----|-----------------|-----------------|----------------------|
| 组织段 | 层级前缀 | 必须有 | 必须有 | 不得有 |
| 组织段 | `Loc_` | 不得有 | 必须有 | 不得有 |
| 组织段 | 模块 | 按语义选用 | 同左 | 按语义选用 |
| 组织段 | 子域 | 按语义选用 | 同左 | 按语义选用 |
| 名词语义段 | （0～N） | 按语义选用 | 同左 | 按语义选用 |
| 动作段 | 动作 | **必须有** | **必须有** | **必须有** |

对应示例：

- `Drv_EncoderUart_HwErrorFlags_Log`（5.1）— `Drv_` + `EncoderUart_` + `HwErrorFlags_` + `Log`
- `Drv_Loc_EncoderUart_HwErrorFlags_AtIrqEntry_Latch`（5.2）— `Drv_Loc_` + `EncoderUart_` + `HwErrorFlags_` + `AtIrqEntry_` + `Latch`
- `EncoderUart_HwErrorFlags_AtRxEvent_Latch`（`static`）— `EncoderUart_` + `HwErrorFlags_` + `AtRxEvent_` + `Latch`
- `Drv_PWM_TargetPulse_Set`（5.1） ↔ `PWM_Pulse_Write`（`static`）— 去掉 `Drv_` 后子域与动作规则一致

#### 4.3.3 层级前缀一览

组织段 ①「层级前缀」的取值（组织段 ② `Loc_` 仅用于纵向层的层内接口，见 4.3.5）：

| 层次 | 路径 | 层级前缀（①） | 层内标记（②，可选） | 示例 |
|------|------|---------------|---------------------|------|
| BSP（横向） | `User/Bsp` | `Bsp_` | — | `Bsp_Init`、`Bsp_TickMs_Get` |

| 服务层 | `User/Service` | `Svc_` | `Svc_Loc_` | `Svc_PendulumService_FeedbackData_Get` |
| 应用层 | `User/App` | `App_` | `App_Loc_` | `App_StateMachine_MainLoop` |

#### 4.3.5 层内跨文件接口（组织段 ② `Loc_`）

**适用范围**：纵向层（App / Service / Drv）内跨 `.c` 调用、且**不是**对上契约的函数。横向模块 Bsp / Common **不使用** `Loc_`。

**必须**：

1. 组织段按 ① + ② 连写为 `层级前缀_Loc_`（如 `Drv_Loc_EncoderTrigger_SendOne`）；
2. 在模块 `.h` 第 **5.2** 区、`.c` 第 **7.2** 区实现（与 5.1 / 7.1 同文件，不另建 internal 头）；
3. Doxygen 加 `@note` 标明层内接口，上层模块**不应**依赖。

仅本文件使用的实现细节仍为 `static`（无 ①②），**不得**进入 `.h` 第 5 区。通过 HAL 回调衔接且仅单文件可见的逻辑，优先保持 `static` 于回调所在 `.c`。

### 4.4 类型、枚举与宏

| 类别 | 规则 | 示例 |
|------|------|------|
| 结构体/枚举类型 | 大驼峰 + `_t` 后缀 | `Status_t`、`PendulumFeedbackData_t`、`RfqFrame_t` |
| 枚举成员 | 全大写 + 下划线，带语义前缀 | `STATUS_OK`、`PENDULUM_SVC_ERR_PARAM` |
| 宏常量 | 全大写 + 下划线 | `DEBUG_PRINTF`、`SPEED_PERMYRIAD_MAX` |

### 4.5 变量命名（匈牙利前缀）

#### 4.5.1 类型前缀

| 前缀 | 含义 | 示例 |
|------|------|------|
| `u8` / `u16` / `u32` | 无符号整数 | `u16Len`、`u32FrameDtUs` |
| `s8` / `s16` / `s32` | 有符号整数 | `s16Pwm`、`s32MotorSpeed` |
| `f` | 浮点 | `fVadc`、`fDtSec` |
| `stru` | 结构体实例 | `struCtrl`、`struFb` |
| `en` | 枚举实例 | `enObject` |
| `au8` / `au16` 等 | 数组 | `au8RxBuf`、`au16RawAdc` |
| `pu8` / `pstru` 等 | 指针 | `pu8Buf`、`pstruSrc` |

#### 4.5.2 作用域前缀

`g_`、`s_`、`ls_` 按**作用域**区分，与存储期无关：

| 前缀 | 作用域 | 放置位置 | 示例 |
|------|--------|----------|------|
| `g_` | 跨文件全局 | `.c` 第 4 区；`.h` 第 4 区 `extern` | `g_au8DebugRxBuff` |
| `s_` | 文件级 `static` | `.c` 第 5 区 | `s_u32MotorSlotSeq`、`s_fMotorCurrentZeroOffsetA` |
| `ls_` | 函数内 `static` | 函数体内 | `ls_au8FeedbackTxBuf` |

文件级 `static` 变量在 `s_` 之后**应当**继续写类型前缀，例如 `s_fMotorCurrentZeroOffsetA`（浮点）、`s_u16TargetPulse`（无符号 16 位）。

函数内普通局部变量（栈上）**仅**使用类型前缀，**不得**使用 `g_` / `s_` / `ls_`。

#### 4.5.3 作用域判定

```
定义在函数外？
├─ 被其他 .c 引用或 extern     → g_，.c 第 4 区 / .h 第 4 区
└─ static，仅本 .c             → s_ + 类型前缀，.c 第 5 区

定义在函数内？
├─ 普通局部（栈）               → 仅类型前缀
└─ static 局部                 → ls_ + 类型前缀
```

## 5. 文件结构与分区

### 5.1 头文件（`.h`）分区

手写模块头文件**必须**按下列顺序组织内容：

| 分区 | 名称 | 内容 |
|------|------|------|
| — | 文件头注释 | `@file`、`@brief`、`@details` |
| 1 | 头文件依赖 | 对外接口所需 `#include` |
| 2 | 宏定义（对外可见） | 对外宏；无则写 `/* 无 */` |
| 3 | 类型定义 | 对外类型；无则写 `/* 无 */` |
| 4 | 对外变量声明 | `extern` 全局变量；默认无 |
| 5 | 接口函数声明 | 全部头文件可见函数原型及 Doxygen；**纵向层**（App / Service / Drv）分 **5.1 上层接口** 与 **5.2 层内接口**（`Loc_`）两个子区；无则对应子区写 `/* 无 */` |

**横向模块** `User/Bsp`、`User/Common` **不拆** 5.1 / 5.2（无层内 `Loc_` 接口，第 5 区保持单区即可）。

**必须**使用 `extern "C"` 包裹第 1～5 区（见模板）。  
各分区即使为空，**必须**保留分区标题并标注 `/* 无 */`。

#### 头文件模板

```c
/**
 * @file    xxx.h
 * @brief   <模块职责一句话>
 * @details 模块路径：`User/Xxx`。<依赖关系、约束说明>
 */

#ifndef XXX_H
#define XXX_H

#ifdef __cplusplus
extern "C" {
#endif

/* ======================== 1. 头文件依赖 ======================== */

/* ======================== 2. 宏定义（对外可见） ======================== */

/* ======================== 3. 类型定义 ======================== */

/* ======================== 4. 对外变量声明 ======================== */
/* 无 */

/* ======================== 5. 接口函数声明 ======================== */

/* -------- 5.1 上层接口 -------- */

/* -------- 5.2 层内接口（层级前缀_Loc_） -------- */
/* 无 */

#ifdef __cplusplus
}
#endif

#endif /* XXX_H */
```

### 5.2 源文件（`.c`）分区

手写模块源文件**必须**按下列顺序组织内容：

| 分区 | 名称 | 内容 |
|------|------|------|
| — | 文件头注释 | `@file`、`@brief`、`@details` |
| 1 | 头文件引用 | 本模块 `.h` 及实现所需头文件 |
| 2 | 私有宏定义 | 仅本文件使用的宏 |
| 3 | 私有类型定义 | 仅本文件使用的类型 |
| 4 | 对外变量定义 | `g_` 全局变量定义 |
| 5 | 私有变量 | `s_` 文件级 static 变量 |
| 6 | 私有函数声明 | 全部 `static` 函数前向声明 |
| 7 | 接口函数实现 | 与 `.h` 第 5 区对应；**纵向层**分 **7.1 上层接口** 与 **7.2 层内接口**（`Loc_`）两个子区，顺序与 5.1 / 5.2 一致；无则对应子区写 `/* 无 */` |
| 8 | 私有函数实现 | `static` 函数实现 |
| 9 | HAL 回调函数实现 | `HAL_*Callback` 等弱符号覆写；无则写 `/* 无 */` |

第 6 区声明、第 8 区实现的分离，旨在使第 8 区内函数实现顺序可按逻辑组织，不受调用先后限制。  
**纵向层**第 7 区**必须**按 7.1 / 7.2 与头文件 5.1 / 5.2 对齐；`User/Bsp`、`User/Common` 第 7 区**不拆**层内子区，可按功能设子节（如 `7.1 系统服务`、`7.2 CRC`）。第 7、8 区内亦可设其他子节（如 `8.1` 编码器快照）。

#### 源文件模板

```c
/**
 * @file    xxx.c
 * @brief   <模块职责一句话>
 * @details <实现依赖、时序与并发约束>
 */

/* ======================== 1. 头文件引用 ======================== */

/* ======================== 2. 私有宏定义 ======================== */

/* ======================== 3. 私有类型定义 ======================== */

/* ======================== 4. 对外变量定义 ======================== */

/* ======================== 5. 私有变量 ======================== */

/* ======================== 6. 私有函数声明 ======================== */

/* ======================== 7. 接口函数实现 ======================== */

/* -------- 7.1 上层接口（与 .h 5.1 对应） -------- */

/* -------- 7.2 层内接口（层级前缀_Loc_，与 .h 5.2 对应） -------- */
/* 无 */

/* ======================== 8. 私有函数实现 ======================== */

/* ======================== 9. HAL 回调函数实现 ======================== */
/* 无 */
```

### 5.3 CubeMX 文件（`Core/`）USER 区映射

CubeMX 生成的 `MX_*` 初始化、`extern` 句柄、`HAL_*_MspInit` 等框架代码**不得**擅自套用分区编号或移动位置。

用户手写内容**应当**集中写入下表规定的 USER 槽位；其余 USER 槽（`Private defines`、`Prototypes`、`PD`、`PV`、`PFP` 等）保持空白。

**`Core/Inc/*.h`**

| CubeMX 标记 | 对应分区 | 内容 |
|-------------|----------|------|
| `USER CODE BEGIN Includes` | 1～5 | 依赖、对外宏、类型、`extern`、接口声明 |

**`Core/Src/*.c`**

| CubeMX 标记 | 对应分区 | 内容 |
|-------------|----------|------|
| `USER CODE BEGIN 0` | 1～6 | 额外 `#include`、私有宏/类型、`g_`/`s_` 变量、私有函数声明 |
| 文件末尾 `USER CODE BEGIN 1` / `4` | 7 | `Drv_*` 等驱动接口实现 |
| 同上区域后半段 | 8 | `static` 私有函数实现 |
| 文件末尾 `USER CODE BEGIN 1` / `2` | 9 | `HAL_*Callback` 实现 |

无用户代码时，上述槽位内仍须保留分区标题；空段统一写 `/* 无 */`，**不得**省略整段。

Cube 文件顶部由生成器插入的 `#include "模块.h"` **不计入**第 1 区。

### 5.4 配置模块 `config.h`

`config.h` 为用户编译开关的**唯一**定义入口，不套用 5.1 节的五段式分区，而采用下列三段：

```c
/* ==================== 1. 编译开关（Compile） ==================== */
/* 决定条件编译走向、构建变体 */

/* ==================== 2. 功能开关（Feature） ==================== */
/* 运行期功能或行为分支 */

/* ==================== 3. 调试开关（Debug） ==================== */
/* 开发调试用途；发布前宜收敛 */
```

**必须**遵守：

- 全工程用户开关仅在 `config.h` 中 `#define`；
- 其他文件仅通过 `#if` / `#ifdef` 使用，**不得**重复定义；
- 使用开关的 `.c` 文件**应当**直接 `#include "config.h"`；头文件仅在对外 API 确实依赖开关类型时才包含，避免无谓传递依赖。

### 5.5 启动与初始化约定

`main.c` 中 CubeMX 模板负责调用 `HAL_Init()` 与 `SystemClock_Config()`。  
`Bsp_Init()` **仅**负责外设 `MX_*_Init()` 及板级启动序列（如 HRTIM 同步启动），**不得**重复调用 `HAL_Init()` 或 `SystemClock_Config()`。  
`Bsp_Init()` **必须**在 `bsp.h` 第 5 区声明。

## 6. 头文件依赖

### 6.1 基本原则

1. **IWYU**：`.c` 与 `.h` 各自包含其直接引用符号的来源头文件；
2. **公私分流**：支撑对外声明的头文件放入 `.h` 第 1 区；仅实现需要的头文件放入 `.c` 第 1 区；
3. **避免循环与传递耦合**：不得依赖「A 包含 B、B 包含 C」的传递包含来间接获得 C 中符号。

### 6.2 推荐包含顺序

1. 标准库头（`<stdint.h>`、`<stddef.h>`、`<stdio.h>` 等）；
2. 工程公共头（`config.h`、`common.h`）；
3. 本模块头文件（`.c` 中）；
4. 其他模块或驱动头文件。

### 6.3 禁止事项

- 在对外头文件中包含仅实现阶段需要的头文件（如 `<string.h>`、HAL 扩展头）；
- 为「方便」在无关模块头文件中 `#include` 整个驱动头；
- 在多个文件中重复定义 `config.h` 已有开关。

## 7. 注释规范

注释采用 Doxygen 格式，**应当**满足下列要求：

| 对象 | 要求 |
|------|------|
| 文件 | `@file`、`@brief`；必要时 `@details` 说明路径、依赖、约束 |
| 对外函数 | `@brief`；有参数/返回值时写 `@param`、`@param[out]`、`@return`；重要约束写 `@note` |
| 复杂私有函数 | 至少 `@brief`；非显而易见的行为写 `@details` |
| 参数名 | `@param` 中的名称**必须**与形参名一致 |

注释**应当**说明设计意图、前置条件、边界与已知陷阱，**不得**复述代码字面含义（如 `i++; // i 加 1`）。

技术性描述（数值范围、单位、帧格式）**必须**与实现保持一致。

## 8. 编码惯例

### 8.1 返回值与状态类型

| 场景 | 约定 |
|------|------|
| 通用成功/失败 | `Status_t`：`STATUS_OK`、`STATUS_ERROR`、`STATUS_BUSY`、`STATUS_TIMEOUT` |
| 模块特有错误 | 自定义结果枚举，如 `PendulumServiceResult_t`、`SimulinkProtocolResult_t` |
| 使能/失能 | `FunctionalState_t`：`PRJ_ENABLE`、`PRJ_DISABLE` |

需要与上层统一的模块，**可以**提供结果枚举到 `Status_t` 的映射函数。

### 8.2 调试输出

| 场景 | 约定 |
|------|------|
| 一般调试日志 | `BSP_LOG_PRINTF(...)`（`bsp.h`，受 `config.h` 中 `DEBUG_PRINTF` 控制） |
| `DEBUG_PRINTF = 0` | 宏展开为空操作，热路径与中断中零开销 |
| 致命兜底 | `Error_Handler` 等场景可使用裸 `printf`，不走 `BSP_LOG_PRINTF` |
| 上电信息 | 可使用 `BSP_LOG_PRINTF_FORCE` |

### 8.3 编译期检查

**应当**优先使用下列手段在编译期暴露错误：

- `#error`：非法开关组合；
- `_Static_assert`：帧长度、枚举范围、结构体大小等不变量。

### 8.4 中断与并发

1. 中断服务程序及 HAL 回调内**仅**执行最短必要逻辑；
2. 与中断共享的变量**必须**使用 `volatile`；
3. 访问非可重入外设或共享数据结构时**应当**采用关中断等临界区保护（参考 `Bsp_Crc16Modbus_Calc`）。

## 9. 软件分层

### 9.1 三条基本原则

1. **纵向分层，单向依赖**  
   业务纵向顺序为 App → Service → Drv → HAL：上层可以 `#include` 并调用下层；**严禁**下层依赖或调用上层。调用链自上而下，**禁止**跨层直连（例如 App 不得跳过 Service 直接调用 Drv）。

2. **经头文件对外接口交互**  
   层与层之间只通过对方 `.h` 中已声明的宏、类型、函数交互；不引用其他模块 `.c` 内的符号，也不调用未在其 `.h` 第 5 区（或第 4 区变量）中声明的接口。上层模块**应当**只依赖第 **5.1** 区接口；第 **5.2** 区 `Loc_` 接口供本层内跨文件协作，见第 4.3.5 节。

3. **横向公共模块**  
   Common、Config、Bsp 为横向模块，可被各纵向层按需使用，但规则各不相同，**不能**笼统写成「横向模块均可调用 HAL」：
   - **Common**：各层可调用 `Cmn_*`；自身仅依赖标准库与 `common.h`，**不得**包含 HAL 头或调用 `HAL_*` / `Drv_*`。
   - **Config**：各层可 `#include`；仅提供编译期开关，无运行期调用。
   - **Bsp**：各层可调用 `Bsp_*` / `BSP_LOG_PRINTF`；对下可调用 `HAL_*`、`MX_*`，**不得**依赖 App 或 Service。

### 9.2 结构示意

```
App（User/App）
  → Service（User/Service）
    → Drv（Core/Src USER 区）
      → HAL / 外设
  → Bsp（User/Bsp）     /* 横向：延时、Tick、CRC、日志等 */
Common（User/Common）   /* 横向：队列、CRC 算法等，不碰 HAL */
Config（User/Config）   /* 横向：编译开关 */
```

### 9.3 各层允许与禁止

| 层级 | 允许 | 禁止 |
|------|------|------|
| App | 调用 `Svc_*`、`Bsp_*` / `BSP_LOG_PRINTF`、`Cmn_*` | 直接调用 `Drv_*`、`HAL_*` |
| Service | 调用 `Drv_*`、`Bsp_*`、`Cmn_*` | 直接调用 `HAL_*` |
| Drv | 调用 `HAL_*`、`MX_*`、`Bsp_*`、`Cmn_*` | 调用 `Svc_*`、`App_*` |
| Bsp | 调用 `HAL_*`、`MX_*`、`Cmn_*` | 调用 `Svc_*`、`App_*` |
| Common | 仅标准库与自身 | 任何 HAL / Drv 头文件及 `HAL_*` / `Drv_*` |

## 附录 A  最小模块示例

### A.1 `example_module.h`

```c
/**
 * @file    example_module.h
 * @brief   示例模块：演示对外接口分区
 * @details 模块路径：`User/Example`。仅依赖 `common.h` 的 `Status_t`。
 */

#ifndef EXAMPLE_MODULE_H
#define EXAMPLE_MODULE_H

#ifdef __cplusplus
extern "C" {
#endif

/* ======================== 1. 头文件依赖 ======================== */
#include <stdint.h>
#include "common.h"

/* ======================== 2. 宏定义（对外可见） ======================== */
#define EXAMPLE_MAX_COUNT   100U

/* ======================== 3. 类型定义 ======================== */
typedef struct
{
    uint16_t u16Count;
} ExampleData_t;

/* ======================== 4. 对外变量声明 ======================== */
/* 无 */

/* ======================== 5. 接口函数声明 ======================== */
/**
 * @brief  读取示例数据
 * @param[out] pstruOut 输出缓冲区
 * @return STATUS_OK 成功；STATUS_ERROR 参数非法
 */
Status_t Example_Data_Get(ExampleData_t *pstruOut);

#ifdef __cplusplus
}
#endif

#endif /* EXAMPLE_MODULE_H */
```

### A.2 `example_module.c`

```c
/**
 * @file    example_module.c
 * @brief   示例模块实现
 * @details 仅包含自身头文件与实现所需头文件。
 */

/* ======================== 1. 头文件引用 ======================== */
#include "example_module.h"

/* ======================== 2. 私有宏定义 ======================== */
#define EXAMPLE_DEFAULT_COUNT   0U

/* ======================== 3. 私有类型定义 ======================== */
/* 无 */

/* ======================== 4. 对外变量定义 ======================== */
/* 无 */

/* ======================== 5. 私有变量 ======================== */
static uint16_t s_u16LastCount = EXAMPLE_DEFAULT_COUNT;

/* ======================== 6. 私有函数声明 ======================== */
static uint16_t ClampCount(uint16_t u16Value);

/* ======================== 7. 接口函数实现 ======================== */
Status_t Example_Data_Get(ExampleData_t *pstruOut)
{
    if (pstruOut == NULL)
    {
        return STATUS_ERROR;
    }
    pstruOut->u16Count = ClampCount(s_u16LastCount);
    return STATUS_OK;
}

/* ======================== 8. 私有函数实现 ======================== */
static uint16_t ClampCount(uint16_t u16Value)
{
    return (u16Value > EXAMPLE_MAX_COUNT) ? EXAMPLE_MAX_COUNT : u16Value;
}

/* ======================== 9. HAL 回调函数实现 ======================== */
/* 无 */
```

> 说明：私有函数 `ClampCount` 未使用层级前缀，符合第 4.3.2 节要求。

## 附录 B  分区合规检查清单

代码评审时可按下列项自检：

- [ ] `.h` 仅含 1～5 区，空段已标注 `/* 无 */`
- [ ] `.c` 含 1～9 区，顺序正确，空段已标注 `/* 无 */`
- [ ] 纵向层（App / Service / Drv）上层接口在 `.h` 5.1 / `.c` 7.1，层内接口在 5.2 / 7.2 且使用 `层级前缀_Loc_`；Bsp / Common 不拆层内子区
- [ ] 函数名符合 4.3.1 模板：组织段（①～④）→ 名词语义段（⑤）→ 动作段（⑥），动作在末尾
- [ ] `static` 文件私有函数无层级前缀、无 `Loc_`
- [ ] 全局变量命名符合 `g_`/`s_`/`ls_` 规则
- [ ] 头文件无传递依赖、无多余 `#include`
- [ ] 对外接口具备 Doxygen 注释
- [ ] `config.h` 开关未在其它文件重复定义
- [ ] 分层调用关系未被破坏
