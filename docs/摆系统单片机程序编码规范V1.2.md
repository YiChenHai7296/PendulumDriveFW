# 1  引言
## 1.1  适用范围
本规范适用于下列代码：
1. **`User/` 目录**下手写模块：Bsp、Common、Service、App、Config；
2. **`Core/Src`、`Core/Inc`** 中位于 `USER CODE` 区域内的用户驱动代码（`Drv_*` 等）；
3. 上述模块对应的头文件与源文件。

下列代码**不强制**套用本规范的分区编号，但位于 `USER CODE` 内的用户新增符号仍须遵循命名与注释要求：
- CubeMX 生成的 `MX_*`、`HAL_*` 框架代码及其 `HAL_*_MspInit` 等；
- `Drivers/` 下 STM32 HAL、CMSIS 等第三方库。

CubeMX 生成代码沿用其自带的 `/* USER CODE BEGIN/END */` 体系；用户写在 `USER CODE` 区内的代码应遵循本规范的分区映射（见 3.3 节）、命名与注释要求。

## 1.2  术语与缩写

| 术语 | 定义 |
|------|------|
| 对外接口 | 在模块 `.h` 第 5 区声明、供其他 `.c` 文件调用的函数、宏、类型或变量 |
| 上层接口 | 纵向层 `.h` 第 5.1 区声明的接口；命名含层级前缀、**不含** `Loc_` |
| 层内接口 | 纵向层 `.h` 第 5.2 区声明的接口；命名含 `层级前缀_Loc_`，仅供同层模块协作 |
| 私有实现 | 仅在模块 `.c` 内可见的 `static` 函数、变量、宏及类型 |
| 纵向层 | App、Service、Drv 等按调用链分层的模块；头/源文件第 5 / 7 区须分 5.1/5.2、7.1/7.2 |
| 横向模块 | `User/Bsp`、`User/Common` 等可被各层共用的模块；不拆分 5.1/5.2、7.1/7.2 层内子区 |
| 分区 | 源文件/头文件中按固定编号划分的逻辑区块（见第 3 章） |
| IWYU | Include What You Use：仅包含本文件直接使用的符号之来源头文件 |
| USER 区 | CubeMX 在 `Core` 文件中预留的 `/* USER CODE BEGIN … */` 槽位 |
| 匈牙利前缀 | 以类型/作用域信息作为标识符前缀的命名方式（见 4.5 节） |

| 缩写 | 全拼 | 含义 |
|------|------|------|
| BSP | Board Support Package | 板级支持包（`User/Bsp`） |
| App | Application | 应用层（`User/App`，前缀 `App_`） |
| Svc | Service | 服务层（`User/Service`，前缀 `Svc_`） |
| Drv | Driver | 用户驱动层（`Core/Src` 中 `Drv_*` 接口） |
| HAL | Hardware Abstraction Layer | STM32 硬件抽象层 |
| Cmn | Common | 公共库（`User/Common`，前缀 `Cmn_`） |

# 2  总则
固件代码须遵循以下设计原则：

1. **软件架构分层清晰**
	- 软件架构须遵循 **App → Service → Drv → HAL** 的单向依赖关系，禁止跨层调用及反向依赖；
	- 各层之间仅允许通过头文件中声明的对外接口进行交互；
	- Common、Config、Bsp 为横向公共模块，可被各层使用；
	- Bsp 模块允许调用 HAL 层接口，Common 模块不得依赖 HAL 层。

2. **接口与实现分离**
	- 头文件仅用于声明对外接口，包括宏定义、数据类型、外部变量及函数原型；
	- 私有宏、私有数据类型、私有变量及私有函数应定义在对应源文件中；
	- 不对外开放的变量与函数必须使用 `static` 修饰，以限制其作用域；
	- 非必要情况下，不得在头文件中暴露模块内部实现细节。

3. **显式头文件依赖**
	- 每个 `.c` 文件必须直接包含其所使用的函数、数据类型及宏定义所在的头文件；
	- 不得依赖头文件之间的传递包含关系获取所需符号；
	- 头文件应仅包含自身所必需的依赖，避免无关头文件的引入。

4. **优先接口访问**
	- 模块间数据交互应优先通过函数接口实现；
	- 非必要情况下，不得通过全局变量直接共享数据；
	- 对于需要跨模块访问的数据，应优先提供读取、写入、查询或配置接口；
	- 确需对外开放的全局变量，名称必须以 `g_` 作为前缀；
	- 对外开放的全局变量应在定义文件中完成定义，并在对应头文件中使用 `extern` 声明。

5. **Allman 大括号风格**
	- 左大括号 `{` 必须独占一行；
	- 右大括号 `}` 应与对应语句保持相同缩进层级；
	- 即使控制语句仅包含一条语句，也必须使用 `{}` 包裹形成完整代码块，不得省略代码块大括号。
	- **例外**：`extern "C" { … }` 互操作块不适用本条（`{` 与关键字同一行为惯用写法），见 **3.1.3**。

6. **缩进要求**
    - 编辑器应配置为“Tab 自动转换为空格”；  
	- 统一使用空格进行缩进，不得使用 Tab 字符；  
	- CubeMX自动生成代码保持其原有格式，不强制修改；
	- 用户在CubeMX自动生成的代码块中增加的代码，与其格式保持一致，使用 2 空格缩进；
	- 用户新增的独立代码统一采用 4 空格缩进；
	- 所有以‘#’开头的，**不需要**缩进。
	- 代码应保持统一的缩进风格，确保在不同编辑器和平台下具有一致的显示效果。

7. **文档化要求**
	- 每个用户创建的源文件和头文件均须编写文件头注释；
	- 每个对外接口均须按照规定格式编写接口注释；
	- 注释内容应准确描述代码功能、参数、返回值及使用限制；
	- 修改代码时，应同步维护相关注释内容。

8. **风格一致**
	- 工程内所有代码均须遵循统一的命名规范、分层规范、注释规范、格式规范及接口规范；
	- 新增代码和修改代码时，应保持与现有模块一致的设计风格；
	- 不得在同一工程内混用不同的编码习惯或个人风格；
	- 对于本文档未明确规定的内容，应优先遵循项目已有实现方式，保持整体一致性。

# 3  文件结构与分区
## 3.1  头文件（`.h`）分区
`User/` 下手写模块头文件**必须**按下列顺序组织内容（模板见 **3.1.1**）；`Core/Inc` 下 CubeMX 外设头文件在 **USER Includes** 槽内套用相同 1～5 区（模板见 **3.1.2**）。

| 分区  | 名称        | 内容                                                                                                           |
| --- | --------- | ------------------------------------------------------------------------------------------------------------ |
| —   | 文件头注释     | `@file`、`@brief`、`@details`                                                                                  |
| 1   | 头文件依赖     | 对外接口所需 `#include`，无则写 `/* 无 */`                                                                              |
| 2   | 宏定义（对外可见） | 对外宏；无则写 `/* 无 */`                                                                                            |
| 3   | 类型定义      | 对外类型；无则写 `/* 无 */`                                                                                           |
| 4   | 对外变量声明    | `extern` 全局变量；默认无                                                                                            |
| 5   | 接口函数声明    | 全部头文件可见函数原型及 Doxygen；**纵向层**（App / Service / Drv）分 **5.1 上层接口** 与 **5.2 层内接口**（`Loc_`）两个子区；无则对应子区写 `/* 无 */` |
- **横向模块** `User/Bsp`、`User/Common` **不拆**上层/层内接口，可按功能区自行选择划分。
- **推荐**使用 `extern "C"` 包裹第 1～5 区（见 **3.1.1** 模板）；纯 C 工程新建模块**可不写**，见 **3.1.3**。  
- 各分区即使为空，**必须**保留分区标题并标注 `/* 无 */`。

### 3.1.1  `User/` 手写模块头文件模板
适用于 `User/App`、`User/Service`、`User/Bsp`、`User/Common` 等**无 Cube 骨架**的 `.h`（`config.h` 除外，见 3.4）。

- **纵向层**（`User/App`、`User/Service`）：第 5 区**须**分 **5.1 上层接口** / **5.2 层内接口**（`Loc_`），与下表一致。
- **横向模块**（`User/Bsp`、`User/Common`）：第 5 区**不拆** 5.1/5.2；按功能设子节即可（如 `/* --- 帧级环形队列 --- */`），**不得**使用 `Loc_` 层内接口命名。

**纵向层模板（App / Service）：**
```c
/**
 * @file    xxx.h
 * @brief   <模块职责一句话>
 * @details 模块路径：`User/Xxx`。<依赖关系、约束说明>
 */

#ifndef XXX_H
#define XXX_H

#ifdef __cplusplus
extern "C" {
#endif

/* ======================== 1. 头文件依赖 ======================== */

/* ======================== 2. 宏定义（对外可见） ======================== */

/* ======================== 3. 类型定义 ======================== */

/* ======================== 4. 对外变量声明 ======================== */
/* 无 */

/* ======================== 5. 接口函数声明 ======================== */

/* -------- 5.1 上层接口 -------- */

/* -------- 5.2 层内接口（层级前缀_Loc_） -------- */
/* 无 */

#ifdef __cplusplus
}
#endif

#endif /* XXX_H */
```

**横向模块示例（Bsp / Common，第 5 区单区）：**
```c
/* ======================== 5. 接口函数声明 ======================== */
/* --- 系统服务 --- */
void Bsp_Init(void);
void Bsp_Ms_Delay(uint32_t u32Ms);
/* --- CRC16-MODBUS --- */
uint16_t Bsp_Crc16Modbus_Calc(const uint8_t *pu8Data, uint16_t u16Length);
```

### 3.1.2  `Core/Inc` 外设头文件模板（CubeMX + USER Includes 槽）

适用于 `Core/Inc/*.h`。Cube 生成的文件头、保护宏、`#include "main.h"`、句柄 `extern`、`MX_*_Init` 原型等**位于 USER 槽外**，不得套用分区编号或移动；用户分区 **1～5** 写在 **`USER CODE BEGIN Includes` … `END Includes`** 内。Drv 层第 5 区须分 **5.1 / 5.2**（见 3.3）。

```c
/* USER CODE BEGIN Header */
/**
  ******************************************************************************
  * @file    xxx.h
  * @brief   CubeMX 生成的文件头（勿删）
  ******************************************************************************
  */
/* USER CODE END Header */

#ifndef __XXX_H__                    /* ← Cube 保护宏，见 4.2 例外；不得改为 XXX_H */
#define __XXX_H__

#ifdef __cplusplus
extern "C" {
#endif

/* Includes ------------------------------------------------------------------*/
#include "main.h"                  /* ← Cube 插入，不计入用户第 1 区 */

/* USER CODE BEGIN Includes */
/* ======================== 1. 头文件依赖 ======================== */
#include "common.h"

/* ======================== 2. 宏定义（对外可见） ======================== */
/* 无 */

/* ======================== 3. 类型定义 ======================== */
/* 无 */

/* ======================== 4. 对外变量声明 ======================== */
/* 无 */

/* ======================== 5. 接口函数声明 ======================== */

/* -------- 5.1 上层接口（Drv_*，供 Service 等上层调用） -------- */

/* -------- 5.2 层内接口（Drv_Loc_*，供 Drv 层内其它 .c 调用） -------- */
/* 无 */

/* USER CODE END Includes */

extern XXX_HandleTypeDef hxxx;     /* ← Cube 生成：句柄声明，位于 Includes 槽外 */

/* USER CODE BEGIN Private defines */
/* USER CODE END Private defines */

void MX_XXX_Init(void);            /* ← Cube 生成：初始化入口 */
void HAL_XXX_MspInit(...);         /* ← Cube 生成（若有） */

/* USER CODE BEGIN Prototypes */
/* USER CODE END Prototypes */

#ifdef __cplusplus
}
#endif

#endif /* __XXX_H__ */
```

### 3.1.3  C/C++ 互操作（`extern "C"`）

`extern "C"` 用于 C/C++ 混编时，避免 C++ 编译器对符号做名字改编而导致链接失败。纯 C 工程由 C 编译器处理头文件时，`#ifdef __cplusplus` 整段被跳过，**无运行期开销**。

| 文件类型                      | 要求                                           |
| ------------------------- | -------------------------------------------- |
| `User/` 手写 `.h`           | 用 `extern "C"` 包裹第 1～5 区（见 **3.1.1** 模板）     |
| `Core/Inc` CubeMX 生成 `.h` | **必须保留**生成器自带的 `extern "C"`，**不得**为统一风格删除或改写 |
| `config.h`                | **可不使用** `extern "C"`（通常仅含编译选项宏，无函数声明）       |

**格式例外**：`extern "C" {` 中左大括号与关键字写在同一行，为 C/C++ 互操作惯用写法，**不适用**第 2 章 Allman 大括号规则。

## 3.2  源文件（`.c`）分区
`User/` 下手写模块源文件**必须**按下列顺序组织内容，**仅 1～8 区**（模板见 **3.2.1**）。`Core/Src` 下 CubeMX 外设 `.c` 在 **USER 0** 槽内为 **1～6** ，文件结尾的 **USER x** 为 **7～9** 区（模板见 **3.2.2**）。

| 分区  | 名称         | 内容                                                                                                 |
| --- | ---------- | -------------------------------------------------------------------------------------------------- |
| —   | 文件头注释      | `@file`、`@brief`、`@details`                                                                        |
| 1   | 头文件引用      | 本模块 `.h` 及实现所需头文件                                                                                  |
| 2   | 私有宏定义      | 仅本文件使用的宏                                                                                           |
| 3   | 私有类型定义     | 仅本文件使用的类型                                                                                          |
| 4   | 对外变量定义     | `g_` 全局变量定义                                                                                        |
| 5   | 私有变量       | `s_` 文件级 static 变量                                                                                 |
| 6   | 私有函数声明     | 全部 `static` 函数前向声明                                                                                 |
| 7   | 接口函数实现     | 与 `.h` 第 5 区对应；**纵向层**分 **7.1 上层接口** 与 **7.2 层内接口**（`Loc_`）两个子区，顺序与 5.1 / 5.2 一致；无则对应子区写 `/* 无 */` |
| 8   | 私有函数实现     | `static` 函数实现                                                                                      |
| 9   | HAL 回调函数实现 | `HAL_*Callback` 等弱符号覆写；**仅在CubeMX生成的外设.c文件中存在。**                                                   |
- 第 6 区声明、第 8 区实现的分离，旨在使第 8 区内函数实现顺序可按逻辑组织，不受调用先后限制。  
- **纵向层**第 7 区**必须**按 7.1 / 7.2 与头文件 5.1 / 5.2 对齐；`User/Bsp`、`User/Common` 第 7 区**不拆**层内子区，可按功能设子节（如 `7.1 系统服务`、`7.2 CRC`）。第 7、8 区内亦可设其他子节（如 `8.1` 编码器快照）。
- 第 9 区**仅**在 `Core/Src` 下 CubeMX 外设 `.c` 中使用；`User/` 手写 `.c` **仅含 1～8 区**。

### 3.2.1  `User/` 手写模块源文件模板（1～8 区）
适用于 `User/**/Src/*.c`。**不含第 9 区**（HAL 回调写在 `Core/Src` 对应外设 `.c` 第 9 区）。

- **纵向层**（`User/App`、`User/Service`）：第 7 区**须**分 **7.1 / 7.2**，与 `.h` 5.1 / 5.2 一一对应。
- **横向模块**（`User/Bsp`、`User/Common`）：第 7 区**不拆** 7.1/7.2 层内子区；可按功能设子节（如 `7.1 系统服务`、`7.2 CRC`、`7.3 printf 重定向`）。

**纵向层模板（App / Service）：**
```c
/**
 * @file    xxx.c
 * @brief   <模块职责一句话>
 * @details <实现依赖、时序与并发约束>
 */

/* ======================== 1. 头文件引用 ======================== */

/* ======================== 2. 私有宏定义 ======================== */

/* ======================== 3. 私有类型定义 ======================== */

/* ======================== 4. 对外变量定义 ======================== */

/* ======================== 5. 私有变量 ======================== */

/* ======================== 6. 私有函数声明 ======================== */

/* ======================== 7. 接口函数实现 ======================== */

/* -------- 7.1 上层接口（与 .h 5.1 对应） -------- */

/* -------- 7.2 层内接口（层级前缀_Loc_，与 .h 5.2 对应） -------- */
/* 无 */

/* ======================== 8. 私有函数实现 ======================== */
```

**横向模块示例（如Bsp，第 7 区可按功能分子节，或不再细分）：**
```c
/* ======================== 7. 接口函数实现 ======================== */

/* -------- 7.1 系统服务 -------- */
void Bsp_Init(void) { /* ... */ }

/* -------- 7.2 CRC16-MODBUS -------- */
uint16_t Bsp_Crc16Modbus_Calc(const uint8_t *pu8Data, uint16_t u16Length) { /* ... */ }

/* -------- 7.3 C 标准库 printf 重定向 -------- */
int fputc(int ch, FILE *f) { /* ... */ }
```

### 3.2.2  `Core/Src` 外设源文件模板（CubeMX + USER 0 / USER x，1～9 区）

适用于 `Core/Src/*.c`（如 `adc.c`、`hrtim.c`、`usart.c`）。**USER CODE BEGIN 0** 内为 **1～6 区**；Cube 生成的句柄、`MX_*_Init`、`HAL_*_MspInit` / `MspDeInit` 等**夹在中部**，不编号；**USER CODE BEGIN x**（本工程常见为 `1`，亦可能为 `2`、`4` ，以 Cube 实际槽名为准）内为 **7～9 区**，且须保留 **7 / 8 / 9** 三个分区标题（见 3.3）。

```c
/* USER CODE BEGIN Header */
/* CubeMX 文件头（略） */
/* USER CODE END Header */

/* Includes ------------------------------------------------------------------*/
#include "xxx.h"                   /* ← Cube 插入，不计入用户第 1 区 */

/* USER CODE BEGIN 0 */
/* ======================== 1. 头文件引用（本文件额外） ======================== */

/* ======================== 2. 私有宏定义 ======================== */

/* ======================== 3. 私有类型定义 ======================== */

/* ======================== 4. 对外变量定义 ======================== */

/* ======================== 5. 私有变量 ======================== */

/* ======================== 6. 私有函数声明 ======================== */

/* USER CODE END 0 */

XXX_HandleTypeDef hxxx;            /* ← Cube 生成：句柄定义 */

void MX_XXX_Init(void)             /* ← Cube 生成：外设初始化（勿套分区号） */
{
  /* USER CODE BEGIN XXX_Init 0 */
  /* USER CODE END XXX_Init 0 */

  /* ... HAL_XXX_Init、通道/GPIO/DMA 等 Cube 生成代码 ... */

  /* USER CODE BEGIN XXX_Init 1 */
  /* USER CODE END XXX_Init 1 */
}

void HAL_XXX_MspInit(...)          /* ← Cube 生成 */
{
  /* ... */
}

/* USER CODE BEGIN x */

/* ======================== 7. 接口函数实现 ======================== */

/* -------- 7.1 上层接口（与 .h 5.1 对应） -------- */

/* -------- 7.2 层内接口（Drv_Loc_*，与 .h 5.2 对应） -------- */
/* 无 */

/* ======================== 8. 私有函数实现 ======================== */

/* ======================== 9. HAL 回调函数实现 ======================== */
/* 无 */

/* USER CODE END x */
```

## 3.3  CubeMX 文件（`Core/`）USER 区映射
CubeMX 生成的 `MX_*` 初始化、`extern` 句柄、`HAL_*_MspInit` 等框架代码**不得**擅自套用分区编号或移动位置。

用户手写内容**应当**集中写入下表规定的 USER 槽位；其余 USER 槽（`Private defines`、`Prototypes`、`PD`、`PV`、`PFP` 等）保持空白。


-  **`Core/Inc/*.h`**

| CubeMX 标记                  | 对应分区 | 内容                      |
| -------------------------- | ---- | ----------------------- |
| `USER CODE BEGIN Includes` | 1～5  | 依赖、对外宏、类型、`extern`、接口声明 |

-  **`Core/Src/*.c`**

| CubeMX 标记                | 对应分区 | 内容                                                                                 |
| ------------------------ | ---- | ---------------------------------------------------------------------------------- |
| `USER CODE BEGIN 0`      | 1～6  | 额外 `#include`、私有宏/类型、`g_`/`s_` 变量、私有函数声明                                           |
| 文件末尾 `USER CODE BEGIN x` | 7～9  | 同一槽内按序：**7** `Drv_*` 等驱动接口 → **8** `static` 私有函数 → **9** `HAL_*Callback`；须保留三个分区标题 |


- 无用户代码时，上述槽位内仍须保留分区标题；空段统一写 `/* 无 */`，**不得**省略整段。
- Cube 文件顶部由生成器插入的 `#include "模块.h"` **不计入**第 1 区。
- 完整骨架见 **3.1.2**（`.h`）、**3.2.2**（`.c`）。


## 3.4  配置模块 `config.h`
`config.h` 为用户选项的**唯一**定义入口，不套用 3.1 节的五段式分区，而采用下列三段：

```c
/* ==================== 1. 编译选项（Compile） ==================== */
/* 决定条件编译走向、构建变体 */

/* ==================== 2. 功能选项（Feature） ==================== */
/* 运行期功能或行为分支 */

/* ==================== 3. 调试选项（Debug） ==================== */
/* 开发调试用途；发布前宜收敛 */
```

**必须**遵守：
- 全工程用户选项仅在 `config.h` 中 `#define`；
- 其他文件仅通过 `#if` / `#ifdef` 使用，**不得**重复定义；
- 使用选项的 `.c` 文件**应当**直接 `#include "config.h"`；头文件仅在对外 API 确实依赖开关类型时才包含，避免无谓传递依赖。

## 3.5  总结

| 路径            | 文件         | 分区范围                             | 说明                               |
| ------------- | ---------- | -------------------------------- | -------------------------------- |
| `User/**/Inc` | 用户模块 `.h`  | 文件头 + **1～5 区**                  | 模板 **3.1.1**；纵向层分 5.1 / 5.2      |
| `User/**/Src` | 用户模块 `.c`  | 文件头 + **1～8 区**                  | 模板 **3.2.1**；无第 9 区              |
| `Core/Inc`    | Cube `.h`  | USER Includes 槽内 **1～5 区**       | 模板 **3.1.2**；槽外 Cube 句柄 / `MX_*` |
| `Core/Src`    | Cube `.c`  | USER 0：**1～6**；USER x：**7～9**    | 模板 **3.2.2**；中间夹 Cube 初始化 / MSP  |
| `User/Config` | `config.h` | Compile / Feature / Debug **三段** | 见 3.4，不用 1～5 区                   |


# 4  命名规范
## 4.1  文件命名

| 规则     | 说明                                                            |
| ------ | ------------------------------------------------------------- |
| 模块源文件  | 小写字母 + 下划线，成对出现，如 `pendulum_service.c` / `pendulum_service.h` |
| 单头文件模块 | 允许仅含 `.h`，如 `config.h`                                        |
| 禁止     | 模块文件名中使用空格、大驼峰                                                |

## 4.2  头文件保护宏

| 规则 | 说明 |
|------|------|
| 格式 | `文件名大写_H`，如 `MOTOR_SERVICE_H`、`BSP_H` |
| 结尾 | `#endif /* MOTOR_SERVICE_H */` |
| 禁止 | 前导或连续下划线（`__XXX__`、`_XXX`），其为 C 标准保留标识符 |
| 例外 | CubeMX 生成的 `Core/Inc/*.h` 采用 `__XXX_H__` 形式（如 `__HRTIM_H__`），**不得**手工修改；用户新建或手写的头文件仍须遵守上表格式与禁止项 |

## 4.3  函数命名
### 4.3.1  统一模板
函数名（头文件声明的接口与 `.c` 内 `static` 私有函数**共用**同一套拼段规则）自左向右由**三类段类**顺序拼接，语义范围**从大到小**；**动作段**有且仅有一个，且**固定在最后**。

**统一模板（从左到右）：**
```text
[组织段：层级前缀_][组织段：Loc_][组织段：模块_][组织段：子域_][名词语义段_…][动作段]
```

**段类总览（按出现顺序）：**

| 顺序 | 段类 | 在模板中的位置 | 作用 |
|------|------|----------------|------|
| 1 | 组织段 | 最前，可含 1～4 个「段」 | 表归属、层内标记与模块内分组 |
| 2 | 名词语义段 | 组织段之后、动作段之前 | 表操作涉及的名词性语义（可连续多个） |
| 3 | 动作段 | **末尾** | 表动词（做什么） |

**段明细（按段类 → 段顺序；与模板从左到右一致）：**

| 顺序  | 段         | 段类    | 是否必须                            | 含义                             | 示例                                                       |
| --- | --------- | ----- | ------------------------------- | ------------------------------ | -------------------------------------------------------- |
| ①   | 层级前缀      | 组织段   | 头文件接口**必须有**；`static` 私有**不得有** | 所属层/库                          | `Bsp_`、`Cmn_`、`Svc_`、`App_`、`Drv_`                       |
| ②   | `Loc_`    | 组织段   | 可选；**仅纵向层层内跨文件接口**              | 层内标记，紧接层级前缀之后                  | `Drv_Loc_`、`Svc_Loc_`、`App_Loc_`                         |
| ③   | 模块        | 组织段   | 可选                              | 源文件对应的功能模块名                    | `PendulumService`、`SimulinkProtocol_`                    |
| ④   | 子域        | 组织段   | 可选                              | 同一 `.c` 内的逻辑分组或外设子系统           | `EncoderUart_`、`ADC_`、`PWM_`、`RFQ_`                      |
| ⑤   | （可 0～N 个） | 名词语义段 | 可选                              | 动作前的名词短语；多个时从大到小；最末段通常为最具体操作主体 | `FeedbackData_`、`HwErrorFlags_`、`AtIrqEntry_`、`Int16LE_` |
| ⑥   | 动作        | 动作段   | **必须**                          | 动词或动词短语，**固定在末尾**              | `Get`、`Set`、`Read`、`Pack`、`Latch`                        |

**拼段规则：**
1. **不是每一段都必须出现**；命名时自右向左（先定动作段，再按需向左补足）按语义从大到小选取各段。  
2. **禁止**动作写在中间或开头（如 `GetFeedbackData`、`Is_Empty`）。  
3. **禁止**多个名词语义段粘连为一个单词（如 `HwErrorFlagsAtIrqEntry` → 应拆为 `HwErrorFlags_AtIrqEntry_`）。  
4. 仅含动作、无名词语义段时，可为 `层级前缀_动作` 或 `子域_动作`（如 `Bsp_Init`、`Drv_PWM_Enable`）。


**三级可见性（决定组织段 ①② 如何出现）：**

| 级别 | 组织段 ① 层级前缀 | 组织段 ② `Loc_` | 声明位置 | 典型命名 |
|------|-------------------|-----------------|----------|----------|
| 上层接口 | 必须有 | 不得有 | 纵向层 `.h` **5.1** / `.c` **7.1** | `Drv_EncoderUart_HwErrorFlags_Log` |
| 层内接口 | 必须有 | **必须有** | 纵向层 `.h` **5.2** / `.c` **7.2** | `Drv_Loc_EncoderTrigger_SendOne` |
| 文件私有 | 不得有 | 不得有 | `.c` 第 6 / 8 区，`static` | `EncoderUart_LatchIdx_Get` |
横向模块 `User/Bsp`、`User/Common` 无层内 `Loc_` 接口，不适用上表「层内接口」行；其头文件第 5 区、源文件第 7 区保持单区，按功能分子节即可。


### 4.3.2  层级前缀一览
组织段 ①「层级前缀」的取值（组织段 ② `Loc_` 仅用于纵向层的层内接口）：

| 层次      | 路径                 | 层级前缀（①）        | 层内标记（②，可选） | 示例                                                    |
| ------- | ------------------ | -------------- | ---------- | ----------------------------------------------------- |
| BSP（横向） | `User/Bsp`         | `Bsp_`         | —          | `Bsp_Init`、`Bsp_TickMs_Get`                           |

| 服务层     | `User/Service`     | `Svc_`         | `Svc_Loc_` | `Svc_PendulumService_FeedbackData_Get`                |
| 应用层     | `User/App`         | `App_`         | `App_Loc_` | `App_StateMachine_MainLoop`                           |

## 4.5  变量命名

### 4.5.1  类型前缀（匈牙利前缀）

| 前缀                   | 含义    | 示例                       |
| -------------------- | ----- | ------------------------ |
| `u8` / `u16` / `u32` | 无符号整数 | `u16Len`、`u32FrameDtUs`  |
| `s8` / `s16` / `s32` | 有符号整数 | `s16Pwm`、`s32MotorSpeed` |
| `f`                  | 浮点    | `fVadc`、`fDtSec`         |
| `stru`               | 结构体实例 | `struCtrl`、`struFb`      |
| `en`                 | 枚举实例  | `enObject`               |
| `au8` / `au16` 等     | 数组    | `au8RxBuf`、`au16RawAdc`  |
| `pu8` / `pstru` 等    | 指针    | `pu8Buf`、`pstruSrc`      |

### 4.5.2  作用域前缀
`g_`、`s_`、`ls_` 按**作用域**区分，与存储期无关：

| 前缀    | 作用域          | 放置位置                           | 示例                                               |
| ----- | ------------ | ------------------------------ | ------------------------------------------------ |
| `g_`  | 跨文件全局        | `.c` 第 4 区；`.h` 第 4 区 `extern` | `g_au8DebugRxBuff`                               |
| `s_`  | 文件级 `static` | `.c` 第 5 区                     | `s_u32MotorSlotSeq`、`s_fMotorCurrentZeroOffsetA` |
| `ls_` | 函数内 `static` | 函数体内                           | `ls_au8FeedbackTxBuf`                            |
- 文件级 `static` 变量在 `s_` 之后**应当**继续写类型前缀，例如 `s_fMotorCurrentZeroOffsetA`（浮点）、`s_u16TargetPulse`（无符号 16 位）。
- 函数内普通局部变量（栈上）**仅**使用类型前缀，**不得**使用 `g_` / `s_` / `ls_`。

- **作用域判定**
```
定义在函数外？
├─ 被其他 .c 引用或 extern     → g_，.c 第 4 区 / .h 第 4 区
└─ static，仅本 .c             → s_ + 类型前缀，.c 第 5 区

定义在函数内？
├─ 普通局部（栈）               → 仅类型前缀
└─ static 局部                 → ls_ + 类型前缀
```
